## Definitely Remove

### `@kovojs/ui` root

**Current exposure:** An empty package root with no app task; every component already has a direct
subpath.
**Evidence:** `packages/ui/package.json` and `public-packages.json`; component imports throughout
`examples/gallery`; `rules/api-surface.md` requires intentional subpaths.
**Assessment:** The root made CLI discovery depend on a non-feature and implied a barrel that did
not exist.
**Recommendation:** Remove the root and discover the installed package through a real finite
component subpath.
**Migration note:** Refuse root imports because binding-to-subpath selection requires app context.

### `@kovojs/headless-ui/*` 38 runtime projections

**Current exposure:** Boolean, filtered-list, focus, geometry, and state projections exported beside
the public attribute builders.
**Evidence:** `packages/headless-ui/runtime-helper-audit.json` records zero direct named imports
from manifest-public facades in authored docs, examples, conformance, and package consumers. It
separately records the nine helpers required by compiler emit; every declaration now carries an
immediate `@internal` or `@generated` tier tag.
**Assessment:** Human consumers have no stable task for assembling these state-machine fragments.
The public `*Attributes` builders are the supported anatomy-level contract.
**Recommendation:** Internalize 29 and expose the nine compiler consumers only through the finite
generated ABI.
**Migration note:** Refuse automatic replacement because selecting an attribute builder and inputs
depends on rendered anatomy.

### `@kovojs/icons#IconRenderResult`

**Current exposure:** A redundant alias whose contract was only `object`.
**Evidence:** Generated glyphs all implement the same result contract; `SPEC.md` §4.1 owns component
rendering, and `@kovojs/core#ComponentRenderResult` is already canonical.
**Assessment:** A second, weaker alias creates vocabulary without an icon-specific capability.
**Recommendation:** Remove it and generate every glyph against `ComponentRenderResult`.
**Migration note:** Rewrite type imports to `@kovojs/core`.

## Borderline

None remain in this batch. Weak-evidence helpers were resolved conservatively instead of left as

## Should Keep

### `@kovojs/ui/<component>` generated component/props family

The 44 component subpaths are the package-managed and copy-in tasks. The manifest now states parts,
slots, IDs, state inputs, enhancement tier, roles, keyboard behavior, and accessibility behavior.
Card’s six-part contract is tested across source, registry, catalog, README, gallery, and copied
source.

### `@kovojs/headless-ui/<primitive>` public attribute-builder/type family

These subpaths own accessible server-render inputs and attribute construction used by styled and
custom components. They preserve the separation between behavior and copy-in markup without
exposing the internal transition machine.

### `@kovojs/icons` `IconProps` and `@kovojs/icons/<glyph>`

The one shared prop contract and generated glyph-per-subpath family are narrow, searchable, and
supported by a deterministic 1,737-glyph generator. Each glyph returns the canonical Kovo
component render contract.

## Cross-Cutting Recommendations

Keep UI/headless and icons under separate owning generators. Share only the validated catalog
schema and generated search view. Continue treating a generated ABI as public to the compiler, not
as autocomplete for app authors.

## Gaps And Follow-Up

This is the requested Track 5a package-group audit, not a new full-repository audit. The repository
inventory covered all 1,838 manifest-public subpaths so cross-package leaks could be detected, but
the rankings above deliberately cover only UI, headless UI, and icons.
